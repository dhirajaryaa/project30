## What I did

Kicked off Project 30. Decided on a full static architecture — no database, no auth overhead. Config folder holds user/project data as JSON, daily logs live as markdown files in `daily-log/`. Every page reads from the filesystem at build time.

Rewired the entire Next.js app to use `output: 'export'`. Removed MongoDB, better-auth, and all server-side mutations. The developer writes `.md` files, pushes to Vercel, done.

## What I learned

Overengineering is real. The first version had MongoDB, better-auth with Google OAuth, ObjectId casting bugs, and a proxy middleware — all for a single-user static journal. The simplest version is almost always the best version.

Static sites are not "less" — they are focused. No runtime, no cold starts, no broken auth sessions.

## What was difficult

Letting go of the "real app" mental model. A 30-day journal does not need a database. Accepting that was the hardest part.
